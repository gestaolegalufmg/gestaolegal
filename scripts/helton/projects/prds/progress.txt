## Codebase Patterns
- Guarda de unidade mora no **service**, não no controller nem no repositório de
  domínio: método privado `_caso_da_unidade_ativa(caso_id)` que chama
  `CasoRepository.find_by_id(caso_id, unidade_id=RequestContext.get_unidade_ativa())`.
  Já existe em `caso_service.py`, `evento_service.py` e agora em `processo_service.py`.
- Caso de outra unidade responde **404 (NotFoundException), nunca 403** — 403 vazaria
  a existência do caso. Nas leituras que devolvem `| None` o service devolve `None` e
  quem levanta o 404 é o controller.
- `make test` falha com `ModuleNotFoundError: flask` até rodar `uv sync --extra extra`
  (pytest vive no grupo/extra `extra`, o grupo `dev` está vazio). É o que o CI faz.
- Fixtures de unidade em `tests/api/conftest.py`: `auth_headers` (admin, X-Unidade-Id=1/BH)
  e `auth_headers_nl` (mesmo admin, X-Unidade-Id=2/Nova Lima). O admin pertence às duas
  unidades — é com esse par que se prova isolamento sem confundir com falta de permissão.

## 2026-09-05 - f2-unidades-incluir-inativas-api
- `UnidadeRepository.list_ativas()` virou `listar(incluir_inativas: bool = False)`,
  mantendo a ordenação por nome e o comportamento anterior sem o parâmetro.
  `UnidadeService.listar` repassa; `GET /api/unidades/` lê `incluir_inativas` e só
  honra o pedido quando `urole == "admin"`. Não-admin recebe as ativas com 200 (não 403):
  a rota alimenta o seletor do cabeçalho de todo mundo.
- Arquivos: `gestaolegal/repositories/unidade_repository.py`,
  `gestaolegal/services/unidade_service.py`,
  `gestaolegal/controllers/unidade_controller.py`,
  `tests/api/test_unidade_api.py`, `tests/api/test_unidade_repository.py`.
- Três testes de API novos (admin vê inativa, não-admin não vê, PUT ativa=true devolve
  a unidade à listagem sem parâmetro) e o teste de repositório renomeado passou a cobrir
  também `listar(incluir_inativas=True)`.
- Suíte: 348 passed.
- **Learnings for future iterations:**
  - `StringBool` (gestaolegal/utils/StringBool.py) só considera verdadeiro a string
    literal `"true"` — `"1"` vira False. O contrato desta rota é `incluir_inativas=1`,
    então o controller normaliza `"1"` para `"true"` antes de converter. Quem for mandar
    um booleano novo do front por outra rota manda `"true"`/`"false"`, que é o padrão
    do `show_inactive` em todo o web/.
  - Autorização por papel dentro de rota `@authenticated` se lê com
    `RequestContext.get_current_user().urole`; `@authorized("admin")` não serve aqui
    porque barraria os não-admins da rota inteira.

- **Learnings for future iterations:**

    "ESLint output (JSON parse failed...)"; para ler o resultado de verdade, rode

    mascara o código).
