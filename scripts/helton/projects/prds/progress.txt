## Codebase Patterns
- `uv sync` sozinho NÃO instala o pytest: ele está em `[project.optional-dependencies].extra`.
  Sem `uv sync --extra extra`, `make test` cai no `/usr/bin/pytest` do sistema e falha com
  `ModuleNotFoundError: No module named 'flask'` — não é código quebrado, é ambiente.
- `create_app()` sem `config_object` chama `configure_app`, que é onde a validação de subida
  roda. O fixture `app` de `tests/api/conftest.py` usa esse caminho (escopo de sessão), então
  toda validação nova em `configure_app` vale para a suíte inteira.
- Caminho de upload NUNCA em constante de módulo: resolver em runtime via
  `current_app.config["PRIVATE_FILES_ROOT"]`. Constante capturada no import impede
  monkeypatch por teste e congela a config.
- Para trocar a raiz de anexos num teste: `monkeypatch.setitem(app.config, "PRIVATE_FILES_ROOT", str(tmp_path))`.
- `Config` lê env no corpo da classe (import-time). Teste que precise variar um valor de
  `Config` deve usar `monkeypatch.setattr(Config, ...)`, não mexer em `os.environ`.

## 2026-09-05 - f2-migration-eventos-arquivo
- Nova migration `migrations/versions/c4d5e6f7a8b9_eventos_arquivo_300.py`, com
  `down_revision = "b7c1d2e3f4a5"`: `eventos.arquivo` passa de String(100) para
  String(300), para caber a referência relativa dentro da raiz privada (as colunas

- O `downgrade()` conta `LENGTH(arquivo) > 100` antes de reduzir e levanta
  `RuntimeError` com mensagem em português se houver algum — reduzir a coluna com
  valores maiores truncaria as referências em silêncio.
- A migration não move nem reescreve arquivo nenhum; é só o tipo da coluna.
- `gestaolegal/database/tables.py` reflete String(300) em `eventos.arquivo`.
- `uv run alembic -c migrations/alembic.ini heads` mostra `c4d5e6f7a8b9 (head)`,
  head único. `make test`: 348 passed.
- Arquivos: migrations/versions/c4d5e6f7a8b9_eventos_arquivo_300.py (novo),
  gestaolegal/database/tables.py.
- **Learnings for future iterations:**
  - Os testes usam SQLite em memória criado do metadata do SQLAlchemy e NÃO rodam
    Alembic: `make test` verde não diz nada sobre a migration. Quem confere o
    encadeamento é `alembic ... heads` (e `docker compose up -d migrate` para aplicar).
  - Por isso, mexer só na migration sem mexer em `tables.py` (ou vice-versa) passa
    despercebido pelo portão de testes. Os dois andam sempre juntos.
  - `alembic` não está no PATH direto: use `uv run alembic -c migrations/alembic.ini`.
  - Migration que reduz largura de coluna deve checar os dados antes; o padrão do
    repo para downgrade impossível é `pass` com comentário (ver 9b4a1c7e30df), mas
    aqui a redução é possível e só perigosa — daí o RuntimeError.
